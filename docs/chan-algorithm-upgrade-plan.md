# 缠论算法升级规划

## 目标与范围

按用户提供的《缠论》算法分层方案，将当前项目从“分型、严格旧笔、笔中枢和笔级力度观察”升级为可解释、可回放的递归结构分析：

1. 输入经过质量检查、公司行动处理的行情。
2. 识别分型、笔、线段、递归中枢和走势状态。
3. 比较结构力度并识别背驰候选。
4. 结合递归级别、跨周期和市场环境生成有确认条件及失效边界的信号。
5. 用历史回放复核规则和计算成本。

本规划不把图中文字中的“提升胜率 63% 至 76%”当作已验证结论，也不把任何结构信号描述成收益保证。实现后应先回测并披露样本、期间、交易成本和样本外结果。

## 当前实现基线

- 核心算法位于 [`internal/chan/analysis.go`](../internal/chan/analysis.go)、[`internal/chan/turning.go`](../internal/chan/turning.go)、[`internal/chan/segments.go`](../internal/chan/segments.go)、[`internal/chan/recursive.go`](../internal/chan/recursive.go) 和 [`internal/chan/types.go`](../internal/chan/types.go)；缠论页面当前默认请求 `/api/chan/:symbol/adjusted` 并展示 `chan-recursive-v4-preview.11`，旧 `/api/chan/:symbol` 仍保留 `strict-old-bi-v3` 兼容结果。该默认只表示页面使用 preview 结构，不表示预览算法已完成阈值校准或可作为交易策略。
- 日线和周线结构使用独立保存的拆股/分红自动复权 OHLC；日期、OHLC、重复/乱序、未完成 bar、交易日缺口和可疑公司行动会进入质量检查，无法安全衔接的数据会降级并切断结构链。
- 包含处理、严格分型和兼容旧版的笔之外，preview 已实现特征序列线段、形成中状态、同级递归走势和中枢的延伸/扩展/新生关系，以及可追溯的确认时间和输入范围。
- 递归中枢的输入单元范围与中枢所属级别的走势索引分开记录，买卖点扫描使用所属走势索引；笔级三类历史观察单独返回为 `pen_signals`，避免和严格递归信号混用。页面的笔级观察区同时消费这两类兼容来源，顶底卡片优先展示当前有效候选，避免被更早的失效候选遮住。
- `chan-recursive-v4-preview.9` 将分型日期锚定到包含合并组末根行情，同时保留极值来源索引；三类点只接受从中枢范围内穿越边界的首次离开，并以回试端点日期和价格绘制。图区空状态区分当前缩放窗口没有标记、候选尚无绘图坐标和全周期没有信号，避免将历史视窗外的信号误读为算法空白。
- 力度按同方向、同递归级别的已确认走势段积分版本化 MACD；80% 是待历史验证的候选参数，不是已验证结论。背驰与一、二、三类买卖点都保留候选阶段、确认条件、失效边界和信号可见时间。
- S&P 500 环境标签与明确的 `15m → 4h → 1d → 1wk` 递归映射已接入 preview。日线/周线历史使用复权坐标；当前 15 分钟和 4 小时接口仍声明未复权价格坐标，缺少兼容因子时不用于复权日线信号确认。
- `/api/chan/:symbol/adjusted` 返回新旧算法并行结果、复权基准、质量、递归结构及规则证据；SQLite 分开保存复权行情和版本化结构快照。Canvas 在 [`web/static/common/js/chan-client.js`](../web/static/common/js/chan-client.js) 与 [`web/static/common/js/charts.js`](../web/static/common/js/charts.js) 绘制可切换的线段、中枢和信号层。
- 逐 bar 增量 analyzer 已保留并更新包含处理、分型与 MACD 状态，但追加时仍会重建笔之后的线段、递归中枢和信号。逐前缀完整 JSON parity 已有基础覆盖；复杂递归结构/信号非空覆盖与全量对比性能、内存和缓存指标仍在验收。

## 升级后的结构模型

统一使用以下可追溯对象；每个对象都保留所属级别、起止时间、确认时间、输入对象范围和是否仍在形成中：

```text
已调整 K 线
  └─ 包含处理后的 K 线
      └─ 分型
          └─ 笔
              └─ 线段（特征序列规则）
                  └─ 递归中枢
                      └─ 走势方向与背驰候选
                          └─ 分级买卖点候选与环境过滤
```

级别递归使用同一结构定义：上一级别的输入是下一级别已确认结构的端点和价格区间，不是把不同周期按钮简单并列。日线、周线、4 小时和 15 分钟先作为可选观察周期；哪些周期互为上下级、每一级使用哪种结构对象，要在规则规格中固定。

## 分阶段实施

### 阶段一：行情基准和数据质量

**工作项**

- 为缠论历史数据建立独立的复权数据读取和缓存路径；不覆盖期权、现货、常规支撑压力等仍需未复权价格的既有数据。
- 用 `AutoAdjust` OHLC（拆股和分红调整）作为日线结构的主输入；记录数据源、复权方式、抓取时间及规则版本。
- 过滤重复、乱序、非有限数、OHLC 自相矛盾、非交易日和未完成 K 线。对于可恢复的缺失交易日标记断点，禁止结构跨断点连线。
- 让现价与复权后的结构处于同一价格坐标。服务端返回调整基准/换算因子，客户端不得把原始现价直接与复权结构价比较。
- 对拆股、分红、特殊公司行动或无法获得复权数据的标的显示数据质量提示；不能静默回退成看似正常的结构。

**建议数据契约**

- 原始行情继续保留现有字段和接口含义。
- 新增明确标识的 `adjusted_bars` / `adjustment_factor` 数据，不混写进 `price_history`。
- 缓存键包含 symbol、周期、复权类型和数据源；结构缓存另含算法版本。

**验收**

- 有拆股、除息样例的原始与复权 K 线能分别查询；复权 OHLC 仍满足 `low ≤ open/close ≤ high`。
- 缺口、坏数据、未完成 bar 均能解释性地告警，结构对象不会跨缺口连接。
- 图表的历史结构和现价标记使用相同价格基准。

### 阶段二：结构识别（分型、笔、线段、递归中枢）

**分型与笔**

- 保留包含关系处理，但把初始方向、相等极值、方向反转、跳空和同类分型合并等边界写成版本化规则。
- 由用户确认“严格旧笔”是否继续作为唯一笔规则；记录最小间隔、端点极值、确认延迟和快速反转重启方式。
- 未确认的末笔只作为形成中结构；不能参与已确认级别信号。

**线段**

- 按图片建议采用特征序列法，并明确特征序列元素由哪些相邻笔区间组成。
- 采用“标准 1+1 / 特征序列破坏”作为首选规则，但需把以下条件列入算法规格：特征序列包含处理、特征分型、缺口处理、破坏点、反向特征序列确认、线段端点回溯，以及形成中线段更新规则。
- 线段确认日期使用实际可观察到确认条件的日期，不能把未来信息回填到端点日期。

**递归中枢**

- 给定同级别相邻走势段价格区间，定义前三段公共重叠区 `ZG = min(段上沿)`、`ZD = max(段下沿)`；仅在 `ZD < ZG` 时形成中枢。
- 以之后走势段是否与中枢重叠来确定延伸；中枢扩展、新中枢形成、同级别中枢连接/不连接的判据必须明确区分。
- 笔中枢可保留作底层观察对象，但 UI 标签明确标注级别，不能与线段级、走势级中枢混称。

**验收**

- 每根线段和中枢都可追溯到输入笔/走势段索引与确认时间。
- 同一历史输入重复计算，所有已确认端点、确认时间和中枢边界一致。
- 增加新 bar 时，未确认对象允许变化；已确认对象仅在规则允许的历史修正或源数据修订时变化，并记录原因。

### 阶段三：力度与背驰

- 实现 MACD 力度比较，参数固定为 MACD(12,26,9)，并明确 EMA 初始化、预热长度、零轴处理和柱面积积分方法。
- 比较对象必须是相同递归级别、相同方向、可比的走势段；价格新高/新低与力度下降需同时成立，并说明背驰所依赖的同级别中枢/走势背景。
- 斜率和测度作为独立可选指标，不与 MACD 组成未解释的黑盒分数。每种指标单独输出数值、窗口、单位和触发条件。
- 删除将“面积低于 80%”直接当作通用缠论定理的表述；如保留该阈值，须由历史样本验证，并作为版本化参数而非散落的常量。
- 背驰先输出观察状态；后续结构确认前不得显示成确定反转或已完成买卖点。
- 明确背驰阈值的样本验证不局限于日线，使用 30m/60m 级别或宽基标的池进行统计，4h 可作为额外级别对照但不预设其更准确；阈值与周期/结构版本一同记录，日线零信号不作为阈值有效或无效的证据。

### 阶段四：分级信号和环境过滤

- 按规则规格分别识别一、二、三类买卖点，记录级别、对应走势/中枢、结构确认时间、价格条件、未满足条件和失效价。
- 下级别信号的确认只能引用时间上已经完成的低级别结构；信号的确认时间不得早于所需结构的实际完成时间。
- 增加宽基市场环境过滤时，明确基准（建议 S&P 500）、行情周期、方向判定、缺数据时的降级方式，以及过滤是“禁止信号”还是“降低信号状态”。
- 多周期确认要求明确映射关系，例如日线信号是否必须由 4 小时结构确认；未确认要显示等待状态，不能把不同周期的倾向分数包装成历史胜率。
- UI 继续使用“候选/观察/已失效”等状态，展示证据和边界；不提供无条件买卖指令。

### 阶段五：回放、性能和发布

- 建立确定性行情夹具，覆盖包含关系、严格/相等分型、最小间隔、特征序列包含和破坏、线段确认、中枢延伸/扩展、背驰、一二三类买卖点、跳空/拆股、数据缺口和跨周期确认。
- 用时间前推回放避免未来数据泄漏；每个信号只允许使用其确认时已经可见的数据。
- 回测报告至少披露证券和日期范围、样本数、信号后收益窗口、基准、交易成本、最大回撤、胜率置信区间及样本外结果。样本不足时只报告结构覆盖率，不报告胜率结论。
- 先以新算法版本并行计算，与当前 `strict-old-bi-v3` 对照；观察差异并确认 API/UI 能识别规则版本后，再切为默认。
- 增量处理先保证结果与完整重算逐 bar 一致，再做检查点和受影响区间重算。保存足够的回放上下文以支持线段与递归级别修订。
- 回测引擎提供默认关闭的“宽容模式” `AllowFormingSegments`，用于按时间前推回放收集早期形态样本；形成中样本单独统计首次观察、后续确认、撤回及期末仍形成数量，不能混入严格确认样本或宣称为实盘信号。生产分析仍只使用已确认线段。阈值验证是否完成还取决于有效样本和样本外统计，模式开关本身不算完成校准。

## API 与前端改造

- 扩展 Go 结构类型，增加 `Segment`、分级 `Center`、`Level`、结构状态和数据质量元数据。兼容旧字段一段时间，旧 `strokes` 和 `centers` 字段不在新旧含义间静默改名。
- `/api/chan/:symbol` 返回算法版本、复权口径、周期级别、线段、递归中枢、背驰观察、信号确认条件和环境过滤状态。15 分钟、4 小时接口共享结构 schema，并标记各自层级。
- Canvas 增加线段和分级中枢绘制；为不同级别设定可切换图层，避免把所有递归对象同时画在一张图上。悬浮信息展示级别、形成区间、确认时间和状态。
- 缠论说明区展示数据基准、当前算法版本和过滤原因；不改变现货卡片及其他未复权价格模块的价格口径。

以下是图片没有完全定义、需要在实现前形成单独规则规格的项目决策。规划阶段建议采用右侧列中的默认值；如有调整，以冻结后的规则版本为准。

| 规则点 | 建议默认 |
|---|---|

## 交付顺序与完成定义

1. 冻结算法规则规格和数据契约。
2. 加入复权行情独立缓存、质量状态及价格坐标换算。
3. 实现版本化的线段、递归中枢和确认时间。
4. 实现级别化力度、背驰和一二三类信号候选。
5. 加入市场环境与多周期过滤，再接入 Canvas 图层和说明面板。
6. 完成历史回放和性能对比，复核 API 与 UI 显示版本/数据口径。

升级完成的标准是：结构可复现、确认时间无未来信息、价格基准一致、每个信号可追溯并有失效条件、回放结果可复核，并且在升级版本与现有版本间能够解释差异。

## 已知限制与后续计划

**关于信号稀疏与端点敏感性的补充说明**：

1. 已修正一处线段破坏候选的误撤销：上涨线段的特征序列低点被击穿后，反向上行只有越过该中间特征元素高点才视为收复；下跌线段对称要求越过该元素低点。修正后 1,300 根日线样本中 QQQ 从 0 条变为 1 条已确认线段、^GSPC 从 0 条变为 2 条，但仍无连续三条同链交替已确认线段，因此尚未形成递归中枢或背驰信号。该局部修复没有证明其余规则正确，后续仍需用更多市场阶段和周期复核线段及中枢。
2. 算法对窗口起点敏感（QQQ 1,255 根与 1,300 根窗口的笔/线段数量不同）。未来数据隔离回放已覆盖信号时序，但它不会自动消除 warm-up 边界影响；历史回测需固定、配置并披露预热期与统计期，避免把 warm-up bars 纳入收益样本。
3. 30m/60m 聚合管线及 4h 完整区间输入已经可运行；4h 当前按完整交易日 09:30–13:30 的四小时段构造，不把剩余 2.5 小时误标成完整 bar。当前 SQLite 15 分钟历史只覆盖约两个月：QQQ、SPY、AAPL、MSFT、NVDA、ORCL 均有约 1,040 根左右 bar，但质量状态为 degraded；修正后这些盘中样本仍没有已确认线段或递归中枢，数据长度和质量还不足以校准阈值。尚需修复盘中缺失/时间边界来源并扩大历史覆盖与标的池。80% 仍为占位参数，D 组阈值验证保持未完成。
