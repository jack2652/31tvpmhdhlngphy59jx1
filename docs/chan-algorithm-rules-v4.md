# 缠论算法 v4.0.0 规则规格

本文定义本项目 `chan-recursive-v4.0.0` 的可执行规则。由于缠论流派对特征序列、线段破坏、中枢扩展和买卖点存在不同口径，本文明确采用项目口径，避免把某一实现描述为唯一正统定义。所有时间均为行情周期本地交易时间；`confirmed_at` 表示该条件首次可由已收盘行情观察到的时间，不回填为结构极值时间。

本次修订：2026-11-23，Codex；当前实现版本 `chan-recursive-v4-preview.26`。

## 1. 输入、缺口和坐标

- 结构主输入为拆股与现金分红均调整的 OHLCV。输入数据同时保留供应商原始 OHLCV、复权因子、复权类型、供应商和抓取时间；不能确认复权口径时不得标成已复权。
- 价格运算使用 `float64`，比较前按源价格精度归一至最小报价单位；若来源不提供报价精度，则两个价格使用 `1e-8 * max(1, abs(a), abs(b))` 作为相等容差。结构上的严格大于/小于仅在差值超过容差时成立；中枢正宽度也必须超过容差，相触或容差内窄缝/重叠统一按相等处理。图表所用结构价、现价、支持/压力边界必须经过同一个因子映射。
- 校验日期可解析且唯一、时间递增、OHLC 均为有限正数、`low <= min(open, close) <= max(open, close) <= high`、成交量有限且非负。无效 bars 逐条排除并计数；不得默默修补 OHLC。
- 日线缺口按交易日历判断；盘中缺口按该交易时段应有 bar 判断。缺口之后开启新的 `chain_id`，结构不得跨缺口连接。公司行动判断比较原始收盘价、调整收盘价和逐 bar 复权因子：原始价格大幅变化且复权坐标保持连续、因子换算关系成立时输出拆股候选；原始价格下跳并由因子抵消时输出现金分红/现金调整候选。候选名称表示由行情推断的类型，因子验证只证明数值关系，不能替代发行方公司行动记录。两根相邻 bar 均有完整且有效的原始/复权 OHLC 配对时，超过 20% 的调整后价格变动记录为 `large_price_move` 信息事件；幅度低于 50% 时保留结构链，达到 50% 时开启新链。缺少可信配对时，超过 20% 的跳变仍分链。无法解释的大幅复权因子变化或未通过换算校验的价格跳变输出降级质量事件、开启新链并置 `corporate_action_suspected`。
- 日线只使用已完成交易日；周线只在该周所有预期交易日 bars 齐全且最后交易日已收盘后确认。盘中 bar 按区间结束时刻计算收盘，4 小时保留 09:30–13:30 与 13:30–16:00 ET 两段；节假日、提前收市或缺少分段 bar 时不把不完整区间标为完整。

## 2. 包含处理与分型

- 两个相邻合并 K 线区间满足 `A.high >= B.high && A.low <= B.low` 或反向条件时视为包含，边界相等也算包含。
- 首个不包含的相邻对确定方向：高低点均上移为上行，均下移为下行；相等高点时按低点移动方向，相等低点时按高点移动方向。若仍无法确定方向，方向保持未知。方向未知期间的包含区间取并集；方向确定后，上行包含取 `max(high)` 和 `max(low)`，下行包含取 `min(high)` 和 `min(low)`。合并极值相等时保留较晚原始 bar 的索引；合并对象保存覆盖的原始 bar 起止索引。
- 缺口不参与包含关系；缺口断点禁止合并跨断点 K 线，新链从未知包含方向重新开始。
- 顶分型要求中间合并 K 线的高点和低点都严格高于左右邻项；底分型要求两者都严格低于左右邻项。相等极值不构成分型。
- 分型须有左、中、右三个合并 K 线，且右邻项须由其后的第一个不包含 bar 固定；这个固定 bar 收盘后分型才可观察。分型日期锚定中间标准化 K 线吸收的最后一根原始 bar；实际极值的原始索引单独保留，`confirmed_at` 记固定 bar 的收盘时间。末尾未固定分型只作为 provisional，不参与已确认结构。
- 连续同类分型只保留更极端者；极值相等时保留较早者。若替换端点会令前一笔违反笔规则，则旧端点保留并从新分型开启新链。

## 3. 笔、线段和递归级别

- v4 笔规则参考课 81：相邻端点必须异类，中心合并 K 线索引至少相隔 4，顶底方向须正确；不额外要求端点价格区间覆盖途中每根合并 K 线的影线。端点所在分型按上述延迟确认。此前 Go 实现增加的影线包络限制会拒绝参考 Python 实现接受的有效笔，preview.4 起移除该额外条件。
- 同类端点被更极端分型替换时重算未确认末笔；一旦反向有效笔固定端点，前一笔确认时间为反向分型实际确认时间。越过当前锚点而尚无有效反向笔时结束当前 chain 并以新分型重启，保留此前已确认笔。末笔只标为形成中。
- 线段的基础输入为同一 chain 内连续已确认笔。上行线段从底分型开始，其特征序列由线段起点后的下行笔组成；下行线段对称使用上行笔。每个特征元素价格区间等于对应反向笔的 `[low, high]`。特征序列用与第 2 节相同方向性规则合并包含，价格相等时保留较早特征元素。
- 线段需从前三笔区间有交集的有效起点开始；其特征序列由后续反向笔区间构成，包含合并方向由假设线段方向决定。按无缺口特征分型或有缺口后的第二特征序列分型确认结束，线段边界回溯到首个反向笔，`confirmed_at` 取完成定义所需的最后证据笔。当前 Go 状态机已参考 `chan-lun` 的 `find_xds`，但 Go 行情前缀、确认时间和嵌套缺口状态仍待对应确定性夹具验收。
- 只有已确认笔可破坏/确认线段；未确认末笔造成的候选状态单独呈现。端点、组成笔索引、破坏索引和确认时间均须保留。
- 图表 timeframe 是数据采样周期，Chan level 是递归结构级别，两者不等同。每种 timeframe 各自从 bars 计算 level 0 笔和线段；同一 timeframe 的 level N+1 只能消费 level N 已确认线段。递归走势类型按相邻低级别走势区间和中枢状态建立，不把中间线段的算术中点冒充市场分型。当前显式周期映射为 `15m -> 1h -> 2h -> 4h -> 1d -> 1wk`，1 小时、2 小时和 4 小时均由 15 分钟历史按交易时段合成，不把不同周期的 bars 直接拼接。低级别确认尚未到达时，高级结构标为 forming/awaiting，不推断确认。

## 4. 中枢及相邻关系

- 中枢输入是同一 chain、同一递归级别、连续三条已确认走势段（level 0 可额外输出兼容旧 API 的笔中枢）。初始中枢 `ZD = max(segment.low)`、`ZG = min(segment.high)`；仅 `ZD < ZG` 成立，边界相等视为无重叠。
- 后续走势段与固定 `[ZD,ZG]` 严格相交（`low < ZG && high > ZD`）即延伸，中枢边界不随延伸收窄或扩大，结束时间及延伸段数更新。完全不相交的首段结束该中枢。
- 中枢结束后，若之后连续三段形成的新重叠区与旧区有严格交集，记录为扩展关系；否则为新生中枢。新旧区只相接而无严格交集，关系记为相邻不重叠。连续中枢的关系用 `overlap`、`touch`、`separate_up`、`separate_down` 枚举保存；不将中枢延伸误计为新中枢。
- 扩展保留旧中枢对象和边界，另建具有自身组成段的新中枢并以 `expands` 关联；新生中枢以 `new_after` 关联。每个中心含 level、输入对象类型/索引范围、起止日期、确认时间、延伸数、链和原始 ZD/ZG。

## 5. 力度、走势与背驰

- 力度参数为版本化 MACD(12,26,9)：fast/slow EMA 初始值取第一根有效 close，递推 alpha 分别为 `2/13`、`2/27`；DIF=fast-slow，DEA 初值为 0，递推 alpha=`2/10`；histogram=`2*(DIF-DEA)`。头 35 根为预热，不用于背驰信号。
- 每段力度为段起止原始 bar（含两端）对应方向柱值正部之和：上行积分 `max(hist,0)`，下行积分 `max(-hist,0)`。输出积分、起止索引、预热状态和计算版本。比较只允许同 level、同方向、同走势类别、同中心背景的推进段；支持两次离开比较和同中枢进入/离开比较。
- 两次离开背驰观察须同时满足：价格端点严格创新高/低；同向推进段已完成且 MACD 面积正值；当前面积/前次面积 `< 0.80`；两段之间满足同级别、同链的已确认中枢离开/回试背景。回试可全段留在中枢外，或首次进入中枢但不穿越另一侧；穿越中枢的回试不接受。
- 同中枢进入/离开盘整背驰：在笔级及基础线段层比较初始三段之前的已确认进入段与之后的同向离开段。进入段须从中枢一侧穿越至另一侧，离开端点须严格超越进入端点，MACD 同向面积均为正且比值 `< 0.80`；所有中间结构须同链连续并在观察前确认。使用初始固定 ZD/ZG 和 `formed_at`，不等待中枢全部延伸结束。新中枢若在观察前已形成，不再用旧背景比较新的推进；后来才形成的中枢不能抹去更早的观察。
- 笔级盘整背驰的观察时间取离开笔端点分型实际确认时间，整笔尚未固定时仍为 `observing`；反向有效笔固定端点后，以整笔的 `confirmed_at` 转为 `divergence_confirmed`。基础线段层不借用笔分型提前确认，须等待该层线段确认。高阶递归中枢的组成索引属于下一级输入，本次新增进入/离开路径不直接应用于高阶层；原有同级两次离开路径保留。盘整背驰候选不等同于严格趋势背驰。
- 80% 是项目既有筛选参数，不代表理论常数或胜率，本次未针对 QQQ 调参。观察候选触及结构失效价后标为 `invalidated`；失效时间不晚于确认时，不保留该次确认。末笔尚未固定时可延伸或被更极端端点替换，候选可随结构重算变化；不能把观察标记当成确定顶部或底部。
- 斜率指标为 `100 * (end_price/start_price - 1) / max(1, elapsed_trading_bars)`，单位为每根 bar 百分比；测度指标为段持续 bar 数及价格振幅百分比 `100*(high-low)/start_price`。两者只作为解释字段，不单独触发买卖信号。
- 走势状态只取 `uptrend`、`downtrend`、`range`、`departing`、`returning`、`unknown`，分别由同级别中枢相邻关系、已确认线段方向及现价/末结构相对中枢位置决定；未确认对象不改变已确认走势状态。

## 6. 买卖点候选、级别确认和环境过滤

- 一类买卖点候选：同级别推进走势满足第 5 节两次离开背驰或同中枢进入/离开盘整背驰规则，后续结构达到对应路径的确认条件才确认。进入/离开路径允许笔分型已可见、整笔尚未固定的明确观察状态。买点的失效价为该下跌推进端点低价；卖点为上涨推进端点高价。
- 信号扫描的第一层使用 V4 笔和由笔形成的中枢；后续层级使用递归走势及递归中枢。来源类型进入信号和结构 ID，避免同一时间/级别的不同结构碰撞。没有 V4 笔输入时保留递归第零层作为回退输入。
- 一类点尚未获得后续反向线段确认时，可附带生成二类等待状态，明确等待依赖；它不含价格，不作为图表位置或已确认二类点。此项展示候选，不会提前使用形成中结构。
- 二类买卖点候选：一类点之后首次反向完成的次级走势回试，买点回试低价严格高于一类点低价，卖点回试高价严格低于一类点高价；再由本级别恢复方向的线段确认。重复回试不产生新的二类候选。映射周期输入必须同时位于父周期与下级周期各自 `as_of` 截止时间内；任一确认晚于对应快照时都不能生成已确认二类点。
- 三类买卖点候选：离开段可以是中枢最后一条重叠走势段（其端点已离开中枢），也可以是其后重新与中枢相交再离开的走势段。逐次检查独立离开，其后紧邻的首次反方向线段须完成回试且全段严格留在中枢外侧；同一次离开不跳过失败首回试改用后来的回试，中枢外延续不重复触发。买点回试低价 `> ZG`，卖点回试高价 `< ZD`；等于边界按进入中枢处理，不算三类。中枢闭合和首次回试都已确认后才确认三类点；缺少已确认离开或回试时可显示明确等待状态，端点仍可变化。新中枢已经形成后不再用旧中枢生成新的等待或确认事件，高阶中枢通过所属走势索引判断背景替代，不能直接使用下级组成索引。
- 候选发生时间是结构端点时间；可观察时间是最晚所需组成对象的确认时间。缺少必需次级别结构时保持 `awaiting_lower_level`，不得升级为确认信号。失效价分别由结构极值或中枢边界给出，已失效候选不删除。
- 一类点的确认时间独立于其当前状态；若它之后失效，仍可保留失效前已经完整确认的二类历史。二类所需的下级回试和本级恢复必须在父一类点失效之前确认；日期粒度无法确定同日先后时按未确认处理。
- 跨级别映射为 `15m -> 1h -> 2h -> 4h -> 1d -> 1wk`，只允许使用时间上已经确认的直接下一级别对象。用于确认的相邻走势段须同级、同链、时间端点相接且价格端点在统一容差内相等；只共享日期但价格断开不构成连续确认。已确认段必须提供起止时间和不早于结束时间的 `confirmed_at`；参与映射的结构结束与确认时间均不得晚于高、低周期帧各自的 `as_of`。映射的二类点同样受父级及下级帧截止时间限制。API 同时保留 symbol、level、direction、rule version、组成结构、满足/未满足条件、发生/观察/确认时间及失效价格。
- 大盘基准为拆股与分红调整后的 S&P 500 日线。只用截至该信号观察日的 close 和 SMA50/SMA200：`close > SMA50 > SMA200` 为 bull，`close < SMA50 < SMA200` 为 bear，其余为 range；任一 SMA 样本不足或数据不可用为 unfiltered。环境状态与个股结构分开返回；v4 首版只展示过滤状态，不用环境标签删除结构候选。

### 6.1 中枢背景下的独立结构预警

- `structure_warnings_v4` 复用 `V4Signal` schema，始终为数组。只扫描笔级和基础线段第零层：高阶中枢的组成索引属于下级输入，不能直接套用三段规则。独立预警不作为严格一／二／三类点、不派生二类点，也不改变交易计划的六类信号输入。
- 前推进、反向回试、当前推进须同级同链连续，前两段在观察前已确认。中枢初始三段须已形成，使用当时固定的 ZD/ZG；前推进和回试都与该中枢严格相交。不等待整个中枢延伸闭合；观察前已形成新中枢时不继续使用旧背景。
- `center_divergence_sell` / `center_divergence_buy`：当前同向端点严格超越前推进极值；两段 MACD 同向面积均为正、预热完成且后／前面积比 `< 0.80`。图表显示“顶背驰预警”／“底背驰预警”。这是中枢背景下的局部背驰预警，不能冒称严格趋势背驰或一类点。
- `rebound_failure_sell`：下跌回试端点同时低于 ZD 和前推进起点；当前反弹端点低于本轮跌破前高点，且全段最高价严格低于 ZG。反向查找最近已确认、从 ZG 上方跌到 ZD 下方的下跌段，其起点是本轮参考高点；中途反弹触及 ZG 或断链则终止旧轮次。比较本轮参考高点，允许第二次反弹高于第一次但仍未修复原跌破结构。图表显示“反弹承压”；严格三卖依然要求首次回试全段位于 ZD 下方及其原有确认条件。
- `pullback_hold_buy` 为完整买方镜像：上涨端点突破 ZG 和前推进起点，回踩端点高于本轮突破前低点且全段最低价严格高于 ZD；中途回踩触及 ZD 终止旧轮次。图表显示“回踩支撑”。边界相等不满足预警严格条件。
- 笔端点分型实际确认后才产生 `observing`；有效反向笔固定端点后，以整笔 `confirmed_at` 转为 `warning_confirmed`，文字为“预警结构已确认”。基础线段须等本级线段确认，不能借笔分型提前观察。`lower_level_status` / `timeframe_confirmation.status` 为 `not_required`，明确确认仅指本级预警结构。
- 后续行情触及当前端点失效价后保留 `invalidated`。失效不晚于确认时，清除该次确认；晚于确认时保留历史确认。客户端实时价格须先转换到同一价格坐标；本次浏览会话内保留已观察的盘中失效和原确认时间，后续刷新或晚来的固定端点不能复活该预警。报价缺少时间时不编造历史失效日期。
- 同级、同来源、同端点日期和价格、同侧的严格点若在预警观察时已经可见，优先展示严格点；后来才出现的严格点不能抹去更早的预警。每条预警返回中枢／连续段／本轮参考段 ID、证据、缺失条件与实际观察／确认／失效时间。大盘元数据取观察时点，不能借用未来环境。

### 6.2 提前顶部风险与保护价

- `early_risk_warnings_v4` 为独立数组，复用 V4Signal。`early_top_sell`（顶部早预警）和 `early_rebound_sell`（反弹早预警）只用于持仓风险，不进入严格六类点、二类派生或新仓入场判断。
- 左邻、中间、右邻须同数据链且为三根已收盘标准化K线，中间高低价均严格高于左右邻。右邻第一根非包含原始K线为观察时刻；左邻和中间已固定，右邻后续包含不能提前进入观察条件。严格分型仍等待第四根非包含K线固定右邻。
- 只用当时已可见的严格历史分型构建局部假设笔；新顶部须满足既有有效笔距离与方向规则。假设仅供本函数内部筛选，不能进入公开分型／笔／严格六类点。中枢必须在加入假设笔之前已由严格前缀形成，假设反向笔不能提前制造中枢。
- 顶部衰减复用局部同向推进或同中枢进入／离开比较，MACD同向面积比仍须 `< 0.80` 且完成预热；反弹承压复用6.1的本轮跌破前高点和中枢上沿条件。不采用AF StochZ或标的专用阈值，同一顶部形态只列一条风险。
- `date` 与 `observed_at` 都是实际首次观察日，图上标记也位于该日；`pivot_date` 单独记录参考顶部日期，`price`／`invalidation_price` 为参考顶部价格。`protection_price` 固定为观察原始K线低点，不随未来行情下移。
- 初始为 `observing`，后续已收盘K线收盘价严格低于保护价时转 `risk_triggered`（收盘失守预警保护价）。这只是风险增强，`confirmed_at` 始终为空，不能转成严格确认。后续高价触及顶部或数据链断开时 `invalidated`，保留真实阶段记录。同根行情既触顶又失守保护价时优先终止该顶部假设，不能推断根内先后顺序。
- 客户端现价触及保护价立即更新持仓风险卡，无需等待完整反向笔／三卖；触及状态在本次浏览会话中跨报价恢复和历史刷新保留。新信号ID、不同标的或复权坐标变化不继承旧事件。严格低点保护位继续独立保留，不会因新增风险价下移。
- 服务、Yahoo和Alpaca盘中数据缓存为30秒。股票各盘中周期在15分钟边界后35秒检查对应已闭合区间，期货页也按15分钟边界刷新；异步刷新、并发去重与失败冷却保留。Alpaca每天完整补齐六个月历史，日内只重取最近一周并覆盖修订。数据源可能延后，35秒是尝试刷新时刻，不是数据实时到达保证。
- 固定回放：QQQ 762.86顶部（10-06）于10-07出现早预警，保护价751.75，10-08首次收盘失守；ORCL170.07顶部（9-08）于9-09出现早预警，保护价约159.77，9-10首次收盘失守。相比原有结构观察各提前一根日K线。全历史与逐日前缀／增量一致，原严格信号和6.1预警除版本外相同；这不表示能够精准预测最高点或已完成收益验证。

## 7. 算法版本、配置和兼容性

- 当前旧算法版本保持 `strict-old-bi-v3`。新规则身份固定为 `chan-recursive-v4.0.0`；实现未达到 v4 输出契约前，响应不得冒称 v4。
- 参数序列化使用稳定 JSON 对象并包含规则版本、时间周期、报价精度、笔最小间隔、MACD 参数、预热长度、背驰阈值、最大数据缺口和周期递归映射。所有默认值见上文；每次计算结果记录参数 JSON 的 SHA-256。
- 改变确认时点、包含/分型/笔/线段/中枢/信号定义时提升主版本；只增加不改变语义的元数据时提升次版本；修正不影响结构结果的缺陷时提升补丁版本。不得原地覆盖不同算法版本的缓存。
- 旧 API 的 `strokes` 和 `centers` 继续表达 `strict-old-bi-v3` 的笔与笔中枢。原始与复权分析入口均调用同一个递归六类信号引擎；六类结构点只由 `signals_v4` 提供。`signals` 只保留普通笔顶底转折预警，`pen_signals` 为兼容字段且固定为空数组。v4 结构字段包括 `segments`、`recursive_centers`、`recursive_levels`、`quality`、`adjustment` 和 `signals_v4`；旧笔结构字段语义不因信号源合并而静默改写。

## 8. 确定性和时间前推不变量

- 对相同规范化输入、算法版本和参数 JSON，确认对象的字段和顺序稳定；浮点输出以源精度序列化。
- 流式逐 bar 与全量重算在相同前缀上必须产生相同已确认对象；只允许 forming 对象变化。数据源修订须记录修订范围、旧/新值和重算时间。
- 已确认信号的全部必需结构须在确认时可见；观察状态可引用已确认分型所限定、尚未固定的末笔，或明确等待中的离开/首回试，必须列出未满足条件，不得将其冒充已确认结构。回放逐 bar 前推，不允许使用未来 bars、回填确认时间或在历史时点使用后续市场分类。
- 回测若样本不足，报告覆盖率和样本数，不报告胜率结论。任何性能或收益结论需报告代码版本、标的、期间、基准和计算环境。
