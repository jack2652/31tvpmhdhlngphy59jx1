# 缠论算法 v4.0.0 规则规格

本文定义本项目 `chan-recursive-v4.0.0` 的可执行规则。由于缠论流派对特征序列、线段破坏、中枢扩展和买卖点存在不同口径，本文明确采用项目口径，避免把某一实现描述为唯一正统定义。所有时间均为行情周期本地交易时间；`confirmed_at` 表示该条件首次可由已收盘行情观察到的时间，不回填为结构极值时间。

## 1. 输入、缺口和坐标

- 结构主输入为拆股与现金分红均调整的 OHLCV。输入数据同时保留供应商原始 OHLCV、复权因子、复权类型、供应商和抓取时间；不能确认复权口径时不得标成已复权。
- 价格运算使用 `float64`，比较前按源价格精度归一至最小报价单位；若来源不提供报价精度，则使用 `1e-8 * max(1, abs(price))` 作为相等容差。图表所用结构价、现价、支持/压力边界必须经过同一个因子映射。
- 校验日期可解析且唯一、时间递增、OHLC 均为有限正数、`low <= min(open, close) <= max(open, close) <= high`、成交量有限且非负。无效 bars 逐条排除并计数；不得默默修补 OHLC。
- 日线缺口按交易日历判断；盘中缺口按该交易时段应有 bar 判断。缺口之后开启新的 `chain_id`，结构不得跨缺口连接。公司行动判断比较原始收盘价、调整收盘价和逐 bar 复权因子：原始价格大幅变化且复权坐标保持连续、因子换算关系成立时输出拆股候选；原始价格下跳并由因子抵消时输出现金分红/现金调整候选。候选名称表示由行情推断的类型，因子验证只证明数值关系，不能替代发行方公司行动记录。无法解释的原始价、调整价或因子突变输出质量事件、置 `corporate_action_suspected` 并降级；相邻可用交易日间隔内切断结构链。
- 日线只使用已完成交易日；周线只在该周所有预期交易日 bars 齐全且最后交易日已收盘后确认。盘中 bar 按区间结束时刻计算收盘，4 小时保留 09:30–13:30 与 13:30–16:00 ET 两段；节假日、提前收市或缺少分段 bar 时不把不完整区间标为完整。

## 2. 包含处理与分型

- 两个相邻合并 K 线区间满足 `A.high >= B.high && A.low <= B.low` 或反向条件时视为包含，边界相等也算包含。
- 首个不包含的相邻对确定方向：高低点均上移为上行，均下移为下行；相等高点时按低点移动方向，相等低点时按高点移动方向。若仍无法确定方向，方向保持未知。方向未知期间的包含区间取并集；方向确定后，上行包含取 `max(high)` 和 `max(low)`，下行包含取 `min(high)` 和 `min(low)`。合并极值相等时保留较晚原始 bar 的索引；合并对象保存覆盖的原始 bar 起止索引。
- 缺口不单独改变包含方向，但缺口断点禁止合并跨断点 K 线。
- 顶分型要求中间合并 K 线的高点和低点都严格高于左右邻项；底分型要求两者都严格低于左右邻项。相等极值不构成分型。
- 分型须有左、中、右三个合并 K 线，且右邻项须由其后的第一个不包含 bar 固定；这个固定 bar 收盘后分型才可观察。极值日期回填到产生极值的原始 bar，`confirmed_at` 记固定 bar 的收盘时间。末尾未固定分型只作为 provisional，不参与已确认结构。
- 连续同类分型只保留更极端者；极值相等时保留较早者。若替换端点会令前一笔违反笔规则，则旧端点保留并从新分型开启新链。

## 3. 笔、线段和递归级别

- v4 笔规则参考课 81：相邻端点必须异类，中心合并 K 线索引至少相隔 4，顶底方向须正确；不额外要求端点价格区间覆盖途中每根合并 K 线的影线。端点所在分型按上述延迟确认。此前 Go 实现增加的影线包络限制会拒绝参考 Python 实现接受的有效笔，preview.4 起移除该额外条件。
- 同类端点被更极端分型替换时重算未确认末笔；一旦反向有效笔固定端点，前一笔确认时间为反向分型实际确认时间。越过当前锚点而尚无有效反向笔时结束当前 chain 并以新分型重启，保留此前已确认笔。末笔只标为形成中。
- 线段的基础输入为同一 chain 内连续已确认笔。上行线段从底分型开始，其特征序列由线段起点后的下行笔组成；下行线段对称使用上行笔。每个特征元素价格区间等于对应反向笔的 `[low, high]`。特征序列用与第 2 节相同方向性规则合并包含，价格相等时保留较早特征元素。
- 线段需从前三笔区间有交集的有效起点开始；其特征序列由后续反向笔区间构成，包含合并方向由假设线段方向决定。按无缺口特征分型或有缺口后的第二特征序列分型确认结束，线段边界回溯到首个反向笔，`confirmed_at` 取完成定义所需的最后证据笔。当前 Go 状态机已参考 `chan-lun` 的 `find_xds`，但 Go 行情前缀、确认时间和嵌套缺口状态仍待对应确定性夹具验收。
- 只有已确认笔可破坏/确认线段；未确认末笔造成的候选状态单独呈现。端点、组成笔索引、破坏索引和确认时间均须保留。
- 图表 timeframe 是数据采样周期，Chan level 是递归结构级别，两者不等同。每种 timeframe 各自从 bars 计算 level 0 笔和线段；同一 timeframe 的 level N+1 只能消费 level N 已确认线段。递归走势类型按相邻低级别走势区间和中枢状态建立，不把中间线段的算术中点冒充市场分型。首版显式周期映射为 `15m -> 4h -> 1d -> 1wk`，不把周期数据直接拼接。低级别确认尚未到达时，高级结构标为 forming/awaiting，不推断确认。

## 4. 中枢及相邻关系

- 中枢输入是同一 chain、同一递归级别、连续三条已确认走势段（level 0 可额外输出兼容旧 API 的笔中枢）。初始中枢 `ZD = max(segment.low)`、`ZG = min(segment.high)`；仅 `ZD < ZG` 成立，边界相等视为无重叠。
- 后续走势段与固定 `[ZD,ZG]` 严格相交（`low < ZG && high > ZD`）即延伸，中枢边界不随延伸收窄或扩大，结束时间及延伸段数更新。完全不相交的首段结束该中枢。
- 中枢结束后，若之后连续三段形成的新重叠区与旧区有严格交集，记录为扩展关系；否则为新生中枢。新旧区只相接而无严格交集，关系记为相邻不重叠。连续中枢的关系用 `overlap`、`touch`、`separate_up`、`separate_down` 枚举保存；不将中枢延伸误计为新中枢。
- 扩展保留旧中枢对象和边界，另建具有自身组成段的新中枢并以 `expands` 关联；新生中枢以 `new_after` 关联。每个中心含 level、输入对象类型/索引范围、起止日期、确认时间、延伸数、链和原始 ZD/ZG。

## 5. 力度、走势与背驰

- 力度参数为版本化 MACD(12,26,9)：fast/slow EMA 初始值取第一根有效 close，递推 alpha 分别为 `2/13`、`2/27`；DIF=fast-slow，DEA 初值为 0，递推 alpha=`2/10`；histogram=`2*(DIF-DEA)`。头 35 根为预热，不用于背驰信号。
- 每段力度为段起止原始 bar（含两端）对应方向柱值正部之和：上行积分 `max(hist,0)`，下行积分 `max(-hist,0)`。输出积分、起止索引、预热状态和计算版本。比较只允许同 level、同方向、同走势类别、同中心背景的相邻推进段。
- 背驰观察必须同时满足：价格端点严格创新高/低；同向推进段已完成且 MACD 面积正值；当前面积/前次面积 `< 0.80`；两段之间满足同级别中心离开/回试背景。80% 是项目筛选参数，不代表理论常数或胜率。观察候选直到后续反向结构确认才推进状态，触及结构失效价则标为 invalidated。
- 斜率指标为 `100 * (end_price/start_price - 1) / max(1, elapsed_trading_bars)`，单位为每根 bar 百分比；测度指标为段持续 bar 数及价格振幅百分比 `100*(high-low)/start_price`。两者只作为解释字段，不单独触发买卖信号。
- 走势状态只取 `uptrend`、`downtrend`、`range`、`departing`、`returning`、`unknown`，分别由同级别中枢相邻关系、已确认线段方向及现价/末结构相对中枢位置决定；未确认对象不改变已确认走势状态。

## 6. 买卖点候选、级别确认和环境过滤

- 一类买卖点候选：同级别某推进走势离开最后一个已确认中枢，满足第 5 节背驰规则，且后续反向线段确认推进端点。买点的失效价为该下跌推进端点低价；卖点为上涨推进端点高价。
- 二类买卖点候选：一类点之后首次反向完成的次级走势回试，买点回试低价严格高于一类点低价，卖点回试高价严格低于一类点高价；再由本级别恢复方向的线段确认。重复回试不产生新的二类候选。
- 三类买卖点候选：已确认线段离开中枢后，首次反方向线段完成回试且全段严格留在中枢外侧；买点回试低价 `> ZG`，卖点回试高价 `< ZD`。等于边界按进入中枢处理，不算三类。
- 候选发生时间是结构端点时间；可观察时间是最晚所需组成对象的确认时间。缺少必需次级别结构时保持 `awaiting_lower_level`，不得升级为确认信号。失效价分别由结构极值或中枢边界给出，已失效候选不删除。
- 跨级别映射为 `15m -> 4h -> 1d -> 1wk`，只允许使用时间上已经确认的直接下一级别对象。API 同时保留 symbol、level、direction、rule version、组成结构、满足/未满足条件、发生/观察/确认时间及失效价格。
- 大盘基准为拆股与分红调整后的 S&P 500 日线。只用截至该信号观察日的 close 和 SMA50/SMA200：`close > SMA50 > SMA200` 为 bull，`close < SMA50 < SMA200` 为 bear，其余为 range；任一 SMA 样本不足或数据不可用为 unfiltered。环境状态与个股结构分开返回；v4 首版只展示过滤状态，不用环境标签删除结构候选。

## 7. 算法版本、配置和兼容性

- 当前旧算法版本保持 `strict-old-bi-v3`。新规则身份固定为 `chan-recursive-v4.0.0`；实现未达到 v4 输出契约前，响应不得冒称 v4。
- 参数序列化使用稳定 JSON 对象并包含规则版本、时间周期、报价精度、笔最小间隔、MACD 参数、预热长度、背驰阈值、最大数据缺口和周期递归映射。所有默认值见上文；每次计算结果记录参数 JSON 的 SHA-256。
- 改变确认时点、包含/分型/笔/线段/中枢/信号定义时提升主版本；只增加不改变语义的元数据时提升次版本；修正不影响结构结果的缺陷时提升补丁版本。不得原地覆盖不同算法版本的缓存。
- 旧 API 的 `strokes` 和 `centers` 继续表达 `strict-old-bi-v3` 的笔与笔中枢。v4 使用新字段 `segments`、`recursive_centers`、`level`、`quality`、`adjustment` 和 `signals_v4`，迁移期间双写或并行计算；旧字段语义不得静默改写。

## 8. 确定性和时间前推不变量

- 对相同规范化输入、算法版本和参数 JSON，确认对象的字段和顺序稳定；浮点输出以源精度序列化。
- 流式逐 bar 与全量重算在相同前缀上必须产生相同已确认对象；只允许 forming 对象变化。数据源修订须记录修订范围、旧/新值和重算时间。
- 信号仅能引用其 `observed_at` 前已收盘且已确认的行情/结构；回放逐 bar 前推，不允许使用未来 bars、回填确认时间或在历史时点使用后续市场分类。
- 回测若样本不足，报告覆盖率和样本数，不报告胜率结论。任何性能或收益结论需报告代码版本、标的、期间、基准和计算环境。
