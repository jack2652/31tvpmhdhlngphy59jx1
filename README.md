# Option Scope

Option Scope 是一个美股行情与期权分析工具，涵盖现货行情、期权链、成交流向、买方结构和关键价位分析。当前分支提供纯 Go 服务，HTTP 层使用 Gin，数据存入 SQLite；前端是无需 Node 构建的 HTML、CSS 和 JavaScript 静态资源，并通过 `//go:embed` 编入服务二进制。

## Go 服务

当前分支为纯 Go 实现，不依赖其他语言运行环境。交叉编译时使用 `CGO_ENABLED=0`，部署端不需要 Go 工具链、源码或单独的静态资源目录。部署目录需包含对应架构的服务二进制、`run.sh` 和 `.env.example`；SQLite 数据默认保存在 `data/options.db`。

当前 Go 服务入口为 `cmd/go-server/main.go`，使用：

- Gin 路由、中间件、静态资源和 SSE；活跃 SSE 订阅按美东时段及 XNYS 假日、历史临时休市和提前收盘规则调度快照刷新（约 20/60/300 秒），同标的刷新串行合并，失败时退避；
- `modernc.org/sqlite` 通过标准 `database/sql` 读写现有 `data/options.db`，启动时只做兼容性列检查。驱动完全由 Go 实现，不依赖 CGO 或目标机 libc，数据库使用标准 SQLite 文件格式；
- Yahoo 行情、历史、到期日和估值可用能力优先通过 `github.com/wnjoon/go-yfinance` 获取。当前依赖为 `v1.7.0`；期权链只对 SDK 尚未暴露的 Gamma 和缺失值/null 存在性保留窄字段适配，fundamentals timeseries 也只补 SDK 当前未提供的时间序列字段。SDK 增加这些字段/API 后，应优先切回 SDK 并删除对应适配。所有行情适配器共享同一个上游并发门（默认上限 6，`RESOURCE_MODE=auto` 时由启动检测到的可用内存和 CPU 动态收紧），Yahoo、CBOE、Alpaca、估值与刷新统一受此预算约束；基础报价与期限目录使用独立交互通道，低内存下 Gamma、估值基准和历史等重任务仍采用串行或小批次策略；
- 启动时读取当前可执行文件所在目录的 `.env` 中未由进程环境设置的变量（支持 `KEY=value`、引号值、注释及 `export KEY=value`）；默认 SQLite 文件位于二进制旁的 `data/options.db`，`.env` 中的相对 `DATABASE_PATH` 也相对于二进制目录解析。开发时通过 `go run` 启动则以当前工作目录为基准，首次编译和复用编译缓存采用相同规则；原始 Yahoo 补充请求、Cboe、Alpaca 和维护工具 API 请求统一经 `internal/outboundhttp` 构造和发送，Yahoo SDK 请求由 SDK 自己管理连接，但使用同一包提供的 `MARKET_PROXY`、Chrome JA3 和 User-Agent 配置；`RAW_RETENTION_DAYS`（默认 30 天）配置清理保留期；
- 与现有前端兼容的 `/quote`、`/expirations`、`/chain`、`refresh`、`events`、`status`、`health` 路由，以及按 `RAW_RETENTION_DAYS` 清理历史数据、按数据库体积上限阶梯回收冗余快照的 `/api/cleanup`；`SCHEDULER_ENABLED` 开启时还会通过 SQLite 服务租约执行每日维护。

在开发机交叉编译 Linux 发布包（默认 `linux/amd64`）：

```bash
# 直接用 bash 调用，不要求脚本文件具有可执行权限
bash ./scripts/build-go-release.sh linux amd64
# 交叉编译到 ARM64
bash ./scripts/build-go-release.sh linux arm64
```

脚本直接生成 `dist/option-scope-linux-amd64` 单个可执行文件（ARM64 示例见命令），使用 `CGO_ENABLED=0` 和 `-trimpath -ldflags='-s -w'` 构建，并通过 `//go:embed` 将源码目录 `web/static` 内的页面资源打包进去。部署时只需传输该二进制；配置通过进程环境或同目录 `.env` 提供，服务可由 systemd 或其他进程管理器启动。

在开发机运行 Go 验证：

```bash
go test -p 1 ./...
go test -race -p 1 ./...
go vet ./...
```

缠论规则仍在迭代，`internal/chan` 的结构快照 fixture 会随规则版本更新；核心服务包（`internal/server`、`internal/provider`、`internal/store`、`internal/config`）应保持全绿。

服务包含 `/api/flow` 快照分析、Yahoo/Cboe/Alpaca 行情与期权 provider、基于报价的 IV/Gamma、历史日线/极值/Beta 缓存协调、SQLite 服务租约、跨实例快照合并、Gamma 后台分批任务，以及 `/api/levels` 压力位与支撑位分析（包括斐波那契、筹码峰值、承接候选、期权磁吸、合并排序、校准与计划输出）。容量上限阶梯清理和每日维护也由 Go 服务执行。市场 regime 和估值模型均有 Go 测试覆盖。估值模型涵盖金融、REIT、能源/矿业、互联网、公用事业、国防、邮轮、移动科技、重资产转型、芯片及 AI 存储等类别；Yahoo 行情、历史、期权、估值指标和财务报表优先使用 `go-yfinance v1.7.0`，少量补充请求用于 SDK 尚未建模的字段。

项目包含 Go 单元测试、API 契约测试、race 检查、vet、运行脚本保护和交叉编译发布包验证。市场数据依赖外部上游服务；Yahoo 可能限流，Cboe 与 Alpaca 的生产可用性取决于账号权限和上游状态。生产部署前应验证数据源访问、数据库备份恢复和服务恢复流程。

## 能做什么

- 查询指定标的的当前价格、涨跌幅和市场状态。载入标的或切换到期日后，地址栏会写入 `?symbol=` 和 `expiration=`，刷新页面会恢复当前选择；未指定标的时使用 `DEFAULT_SYMBOLS` 的第一项（默认 `QQQ`）。换标的时到期日默认回到新标的的第一个（最近）到期日——各标的到期日序列不同（有的每周五、有的每天、有的半月）；同一标的重复载入则保留当前选择。
- 现货现价按当前时段动态显示：盘前显示盘前价、盘后与夜盘显示盘后价、盘中与休市显示常规价（对应时段没有数据时回退常规价）。卡片同时标注当前时段（盘前 / 正常交易 / 盘后 / 夜盘 / 休市），顶栏也有同样的时段提示。涨跌幅以该时段之前最近一次盘中收盘为基准。优先用行情源正式收盘（含竞价）；它缺失，或与分钟线上一交易日盘中收盘偏离超过 1% 时，改用分钟线收盘，避免日线空掉一根时涨跌幅被放大。
- 现货涨跌幅旁标出计算基准（相对昨收、相对收盘或相对前收）。净 Gamma、零 Gamma、趋势信号、最佳点评分和买方评分都标明为估算，不是成交价或胜率。
- 选择到期日查看 Call/Put 期权链的成交量、未平仓量、买价、卖价、Gamma、GEX 和隐含波动率；表格共 9 列（行权价 / 成交量 / 未平仓 / 买价 / 卖价 / Gamma / GEX / IV（估）/ 价内），所有单元格居中显示，不展示合约代码与最新价。类型不再单独占列：行权价文字绿色即看涨、红色即看跌（保持加粗强调）。期权链面板默认折叠，标题行最右侧是「展开 / 收起」；类型筛选下拉框（全部 / 看涨 / 看跌）放在面板内部、收起面板时随内容一起隐藏，切换只重绘表格、不重新请求数据，重绘时底色按当前显示的行重新归一。成交量与未平仓两列用底色表示强弱：各自按「本屏该列最强值」归一（√ 缩放），黑夜模式填充 10%~78%、白天模式 12%~82%，0 值不着色；底色已经够亮的「热点格」文字自动换成深色墨色，保证亮底上仍然读得清；悬停显示数值与本列最强值占比，表格下方图例标注取色口径与两列的归一基准。GEX 列与 Gamma 敞口图同口径（模型 Gamma × 未平仓 × 100 × 现价² × 0.01，即现价每变动 1% 的美元敞口），看涨为正、看跌为负，整列之和就是 Gamma 面板上的净 Gamma。
- 期权链在正常交易时段沿用主行情接口；盘前、盘后、夜盘和休市自动改用 Cboe 免费延迟期权链接口（无需 API key，接口为 `https://cdn.cboe.com/api/global/delayed_quotes/options/{symbol}.json`），返回逐合约未平仓量、报价、成交量、IV 和 Greeks。Cboe 的未平仓量按上一交易日结算数据理解，不承诺盘外实时变化；接口故障时保留 SQLite 最近快照。
- 主题默认白天模式，右上角一键切换黑夜；偏好写入浏览器 `localStorage`，刷新后保持，首屏由内联脚本引导不会闪色。
- 查看 Gamma 敞口、零 Gamma（Gamma Flip）、看涨墙/看跌墙、成交量分布和持仓量分布。
- 期权流向与买方结构分析：按相邻两份期权链快照的成交量增量，结合最新价相对买卖价的位置估算主动买入、主动卖出和中性成交，并展示 Call/Put 汇总与集中执行价；没有新增成交量、接口失败或本轮期权链暂时为空时保留最近一次有效结果。买方结构按当前期权链和价位分析生成候选，仅供研究参考。
- 压力位与支撑位：支撑位在左、压力位在右（窄屏堆叠时支撑位在上），基准价上下各 10 条，综合四类因子——斐波那契回撤、筹码密集区（按价格分布的成交量）、近期承接位（被打下去又被买回的摆动低点）和所选到期日的 Call/Put 持仓。基准价由折叠组标题栏的开关决定：默认「实时价」（当前时段生效的最新价，盘中为最新成交价，跟随快照刷新，突破行情下不会滞后），可切「盘后价」（盘后成交更接近当日结算价，盘前冲高与盘中回落常是「假突破」；盘前、夜盘与休市都取上一个交易日的盘后价，不使用盘前价或夜盘价顶替；上一交易日确实没有盘后数据时退回该交易日收盘价，卡片标签会同步显示实际口径）。切换只重算压力位/支撑位这一侧，不重新请求上游接口；面板说明里会标注实际基准与口径。同一段价位（基准 0.5% 内）合并成一条并累加权重，按「强度 ÷ (1 + 距基准%)」取前 10，再按离基准由近到远展示；每条标注组成它的因子，悬停可看综合强度（1 为最强）。日线历史抓不到时自动退化为纯期权口径。每行另显示「到达概率」：在所选到期日之前触及该价位的概率，按该到期日隐含波动率、零漂移的首次触及模型（几何布朗运动反射原理）估算，波动率或期限缺失时显示「--」。
- 压力位/支撑位柱状图：位于 Gamma 敞口右侧、同一行两栏，横轴为价位（按价格线性排布），柱高为综合强度（1 为最强），压力位向上（绿）、支撑位向下（红），并用琥珀色竖线标出基准价；悬停显示价位、距现价、到达概率与综合依据。原有的压力位/支撑位表格保留。
- 趋势通道与交易计划：趋势通道按最近 60 根日线收盘价做线性回归，给出上行通道 / 下行通道 / 区间震荡以及通道上下轨与日均斜率，并用 RSI(14) 标出超买、超卖或中性，并列出 52 周最高/最低与历史最高/最低价（取日线最高/最低价，52 周窗口按最后一根日线回推 365 天，历史极值取全量日线，悬停显示发生日期与距现价）；推荐买入价位取现价下方最近的 5 个支撑，加仓价位取更深一档的 5 个支撑，卖出价位取现价上方最近的 5 个压力，三张表的每一行都给出价位、距现价、到达概率与综合依据（组成该价位的因子标签，悬停可看综合强度）。
- 将鼠标或触摸移动到任意图表上，可查看十字虚线（竖线定位价位、横线跟随鼠标高度，两端各带取值标签）和详细数据浮层；Gamma 图额外显示行情价、看涨 GEX、看跌 GEX 和净 GEX。
- 浏览器通过 SSE 保持当前标的连接；仅活跃订阅触发行情自动刷新，服务端按美股交易时段自调度：常规盘约 20 秒、盘前/盘后约 60 秒、休市约 5 分钟；上游连续失败时指数退避，最长 5 分钟。SSE 断开后停止该订阅的刷新；SQLite 租约协调多 worker，避免重复回源。`DEFAULT_SYMBOLS` 仅用于页面默认标的；页面数据随实时推送自动更新。载入标的时优先读取 SQLite 缓存，跨期限 Gamma 窗口在后台异步刷新，不阻塞表格。
- 冷启动把到期日目录与最近到期期权链合并为一次上游请求；低内存模式仍启用 gzip（BestSpeed），缠论图表折叠时按需加载，展开后才请求复权结构。
- 每天按 `RAW_RETENTION_DAYS` 配置分批清理过期的历史行情、期权链、日线历史和刷新运行记录。
- 首次载入一个从未抓取过的标的时，即使本地 SQLite 还没有它的到期日，也会自动回源补全并正常渲染；如果该标的确实没有挂牌期权（例如 OTC 存托凭证 TCEHY），页面只显示现货行情，期权相关面板统一提示「没有挂牌期权（或可用期限已全部到期）」，刷新按钮仍可用于更新现货。
- SQLite 使用 WAL 和索引，适合单机或单实例快速部署。
- 页面自上而下依次为：标的现货与成交统计卡 → 分析详情折叠组（默认展开：趋势通道与交易计划（推荐买入 / 加仓 / 卖出）→ 压力位/支撑位数据表）→ 图表区（Gamma 敞口、压力位/支撑位柱状图、成交量分布、持仓量分布）→ 缠论分析（日线／周线位置、笔中枢图和走势观察条件，默认折叠）→ 期权流向与买方结构分析（默认折叠）→ 期权链明细（默认折叠）。所有折叠组及缠论内部的折叠项都在 sessionStorage 中保存手动选择，同一标签页内切换标的、刷新页面均保留，卡片顺序变化不影响保存状态。没有记录时，趋势分析与图表组默认展开，缠论、期权分析、期权链及缠论内部折叠项默认收起；重新打开标签页使用默认状态。

配色沿用美股行情惯例「绿涨红跌」：上涨、看涨（Call）、压力位统一为绿，下跌、看跌（Put）、支撑位统一为红。颜色令牌集中在 `web/static/common/css/styles.css`：黑夜主题（默认）在 `:root`，白天主题在 `:root[data-theme="light"]`，两套同名令牌一一对应。

主行情接口在这里提供的是行情和盘中期权链快照，Cboe 公共接口提供盘外延迟期权链；两者都不是交易所逐笔成交流，也不保证每分钟都有新的市场数据。Cboe 的未平仓量属于上一交易日数据，适合盘前、盘后和夜盘分析但不是盘外实时 OI。生产使用前请确认所用行情数据源的使用条款与授权范围。

Gamma 敞口使用 Black-Scholes 根据标的价格、执行价、隐含波动率和到期时间估算，并按看涨正值、看跌负值汇总。零 Gamma 将标的价格作为变量，在近 7 天未到期合约上重新计算总 GEX，到期时刻按美东 16:00 处理，使盘中 0DTE 仍计入；扫描现价 ±15% 后二分求根，多根时取距离当前股价最近的根。柱状图、看涨墙和看跌墙仍使用近 45 天，避免墙位被当天到期合约完全淹没。这些指标是分析估算，不代表交易商真实库存或完整市场 Gamma。

压力位/支撑位的四类因子：斐波那契回撤取回看 120 根日线里由收盘价确认的摆动高低点，按 23.6% / 38.2% / 50% / 61.8% / 78.6% 计算（50% 与 61.8% 权重最高），单根插针不会重画整组回撤；筹码分布把每根日线的成交量按当日价格区间做三角分配后汇总成价格剖面，取最密集的价位；承接位取近 60 个交易日内「被砸下去又收回（长下影，或随后反弹达到约 0.5 倍 ATR）、且之后没有被跌破超过约 0.25 倍 ATR」的摆动低点，越近、越放量权重越高；期权持仓按所选到期日聚合绝对 GEX（整链未平仓量不足成交量 20% 时退回成交量），行权价在现价上方视为压力侧磁吸、下方视为支撑侧磁吸，标签仍标明该价位主要是看涨还是看跌。技术面候选同样按价位落在现价哪一侧归入压力或支撑，同段价位合并后按权重和累加强度。

### 零 Gamma 的公开算法依据

项目采用的是公开资料中常见的“spot-shift GEX profile”口径，而不是按执行价柱子的累计和直接猜测。主要参考：

- [SpotGamma：Gamma Flip](https://support.spotgamma.com/hc/en-us/articles/15413261162387-Gamma-Flip)：将 Gamma Flip 定义为做市商估算 Gamma 正负切换的价格。
- [ZeroGEX：Gamma Flip Calculation](https://zerogex.io/guides/gamma-flip-calculation-before-vs-after)：公开说明近似实现，使用 `Gamma × OI × 100 × S² × 0.01`，Call 为正、Put 为负，在假设的标的价格网格上重新计算 Gamma。本工具未采用其 `DTE/5` 多期限权重，因为个股盘中 0DTE 会被过度压低，导致 AAPL 这类标的零点明显偏离现价。
- [Quant Data：What Is Zero Gamma](https://quantdata.uk/guides/what-is-zero-gamma)：给出近 45 天、冻结 IV、现价 ±10% 搜索区间等可复现选择。

不同平台的零 Gamma 不会天然相同：富途、SpotGamma 等可能使用不同的期权数据时刻、到期日范围、隐含波动率来源、未平仓量过滤和 0DTE 权重。当前工具使用上游快照，因此目标是口径透明、结果可复算，而不是承诺与某个商业平台逐分复刻。

### 缠论：日线与周线

页面的「缠论 · 当前位置与走势推演」独立于期权到期日。日线判断当前价相对最近笔中枢的位置，周线由完整交易周的日线汇总，提供更长周期的结构背景。面板展示 K 线、已确认笔、形成中的笔、中枢区间、相邻中枢移动方向和后续上涨／震荡／下跌的触发与失效条件。

价格结构图支持与 Gamma 图一致的十字虚线：竖线定位最近 K 线，底部显示日期；横线跟随鼠标高度，右侧显示对应价格，与现价标签重叠时移至左侧。数据卡悬浮在图表上沿，显示日期、当前周期和开盘／最高／最低／收盘价；周线显示该完整交易周汇总的 OHLC。切换日线／周线或历史数据更新时清除旧提示。移动鼠标和触摸均可查看，键盘聚焦图表后用左右键逐根查看，Home / End 跳到首根／末根，Escape 关闭提示。

页面先展示「现在怎么看」：由近期笔高低点、已收盘价格和页面现价生成当前判断，列出观察价位、距现价幅度、形成时间与确认状态。后续路径优先说明近端反弹改善或低点失守，再说明原中枢修复；分别标明现价越过、收盘越过和后续结构待确认。周线中枢尚未形成时显示可用日线判断及周线笔数，不以笼统的「等待日周结构完整」覆盖已有日线信息。此处的近端价位解读不新增缠论买卖点，也不代表已确认趋势反转。

「错过底部／顶部，现在怎么做」默认折叠，展开后分别回答未持仓的入场判断和已持仓的持有／退出判断。操作建议、术语说明与抄底／逃顶识别依据为三个独立折叠项，可分别展开。术语说明宽屏按双列排列，最后一项占满整行，窄屏改为单列。旧候选已失效或未识别力度衰减时，仍依据最新连续笔链判断趋势回踩、保护位及反抽失败，避免只显示「等待信号」。已固定低点和抬高的回踩结构可供后续介入评估，不要求成交在最低价；现价从高点回落时，分别说明仍可持有、先减仓和反抽失败后退出的条件。

操作卡片使用价格变化的文字说明：下跌后出现有效反弹、反弹后的回落守住低点、跌破后反弹未能涨回等。卡片前的「这段走势怎么理解」结合当前周期的实际起止价格，解释最新波段、反向笔及现价相对端点的变化；已有上涨波段但入场条件不足时，提示「已有反弹，等待回落企稳」。可展开「术语怎么理解」查看笔、反向笔、回踩、反抽、确认状态、保护位、ATR、空间比例及中枢的文字解释。

- 入场筛选同时需要有效反向笔／底部候选、第三类回试候选或可观察的低点抬高与高点改善结构。现价触及保护位、最近收盘已失守保护位或存在有效卖出风险时，暂停入场。
- 入场距离以当前价到最近已固定低点计算，最多为 2 倍 ATR(14)；ATR 使用最近 14 根已收盘 K 线的真实波幅均值。首个上方观察位取现价之上的最新笔高点、更高的历史已固定高点或当前中枢边界；被最新笔高点越过的旧高点不因小幅回落重新充当首个上方目标。空间至少为风险距离的 2 倍。不满足时提示等待回踩或新结构；没有上方观察位时不虚构上涨目标。这两个阈值是本项目的入场过滤规则，不是缠论定理或胜率，空间／风险比例不代表预期盈亏，也没有扣除费用。
- 有效底部反向笔出现且距离与空间条件满足时，可列为小仓试探；首次回踩守住并有收盘突破、有效第三类候选或趋势回踩依据进一步满足时，提示分批介入。周线位于中枢下方时，日线入场仍标为逆势试探，不升级为加仓判断。
- 持仓保护位采用已固定低点；同一连续笔链中，更低的新低不用于下移原保护位，后来更高低点固定后才更新保护位。页面会话内保留保护位触及，价格恢复及历史刷新不会直接重置；同时检查现有图表行情中的历史触及，连续笔链重建后重新计算。现价触及时提示控风险，收盘失守后先减仓，已固定反抽仍未收回失守前低时退出优先。有效顶部反向笔出现时评估先减仓；已固定回落低点被收盘跌破且现价仍在下方时退出优先。只有形成中的力度衰减时提示守住保护位，不视为已经确认顶部。旧顶部候选失效不单独触发卖出或买回。
- 页面同时展示距保护位幅度、每股风险距离、ATR 倍数和观察空间／风险比例。这些是基于结构的条件式判断，未读取个人持仓、成本和风险预算，不确定仓位比例；保护位不保证成交价，实际跳空、费用和盘中变化需另行处理。

抄底、逃顶信号的识别阶段为：

1. **力度衰减观察**：向下笔创新低或向上笔创新高，且相较前一同向笔的 MACD 同向柱面积减小。末笔仍在形成，极值和面积都可能变化。
2. **反转候选**：有效反向笔出现，原低点或高点被固定；列出首次回踩／反抽需要守住的原始极值，以及反弹高点／回落低点。反向笔尚未固定时，价格观察位也会延伸。
3. **首次回试候选**：首次回踩笔已固定且低点高于原低点，或首次反抽笔已固定且高点低于原高点；继续核对收盘是否越过反向笔端点，并跟踪回试改善是否受损。

每条信号显示原始极值、失效边界、MACD 面积比、具体观察条件和识别日期。图上的「底观察／底候选」「顶观察／顶候选」标在原始极值处，实际识别在之后发生；两种日期不能混用。触及原始极值后，候选失效，即使价格恢复也不会复活同一次候选。没有信号时，说明行情长度、中枢或力度条件缺少哪一项。

兼容的传统缠论日线／周线字段规则版本为 `strict-old-bi-v3`：

- 包含关系按已知方向合并；初始方向未知时保留区间并集；相等极值不形成严格分型。
- 旧笔采用合并 K 线间隔：顶底分型中心至少相隔 4 根，端点必须为区间极值。分型右侧 K 线结束合并后才确认；末笔等待有效反向笔固定端点。
- 笔中枢取三根连续已确认笔的严格重叠区；后续相交笔延伸中枢，保留原始上下沿。日线／周线是图表周期，笔中枢不是完整递归级别中枢。
- 未收盘日线、抓取时尚未收盘且未更新的日线、未完成或缺少交易日日线的周线均不参与结构确认。
- 历史存在交易日缺口时，从缺口后的连续日线重建结构；快速反向波动导致严格旧笔无法接续时，从新的分型重新识别连续笔链，页面注明重建起点。
- 本项目的笔级反转观察要求两根相邻同向笔都与同一已形成笔中枢相交，当前笔的端点越过前一同向笔端点及中枢外沿，且 MACD(12,26,9) 同向柱面积低于前一同向笔的 80%。中枢须在观察时已形成；观察时已有至少 60 根收盘 K 线，前一比较笔起点避开前 35 根预热区，两笔同向柱面积均大于零。80% 是本项目的筛选阈值，不是缠论定理或胜率。
- 只检查最近四根笔，每侧保留最近一次观察；有效反向笔固定极值后晋升候选，首次已固定回试严格守住原极值时显示回试阶段。首次识别、极值固定和回试识别各用当时可见的日期，不回填成极值当天已可交易。力度衰减和首次回试形态不直接命名为完整趋势背驰、一类或二类买卖点。
- 第三类买卖位置按笔回试列为候选，保留识别时间和失效边界。底部／顶部候选从首次识别后持续检查原始极值边界，阶段变化不重置失效记录。页面会话内观察到的失效在重新读取历史后仍保留；重新打开页面时按已收盘行情和现价重算，无法恢复未记录的盘中触及。

兼容字段提供结构位置、抄底／逃顶候选与条件式推演。行情读取现有 SQLite 日线缓存；缺失或过期时复用后台预取和 SSE 更新。该字段沿用未复权 OHLC，拆股和除息跳空会影响结构。

### 缠论递归算法升级预览

新算法的目标规则版本为 `chan-recursive-v4.0.0`，当前 API 标记为 `chan-recursive-v4-preview.9`。`preview` 表示实现仍在升级与验收，不能将其称为正式 v4。旧字段 `strokes` / `centers` 继续使用 `strict-old-bi-v3` 语义；递归结构使用 `segments`、`recursive_centers`、`recursive_levels`、`strengths_v4` 和 `signals_v4`。较宽松的笔级历史观察单独位于 `pen_signals`，不可当作递归买卖点或混入阈值统计。

- `GET /api/chan/{symbol}/adjusted` 使用拆股与分红自动复权的日线历史计算日线、完整周线结构；图表结构与现价需使用响应中的同一复权坐标。历史复权数据缺失或现价换算因子无效时，响应会降级并停止不兼容的现价比较，不静默回退到未复权价格。
- `GET /api/chan/{symbol}/intraday?period=15m|4h` 只处理已收盘的盘中 bars，并复用 v4 递归结构 schema；这些盘中输入仍在原始价格基准内计算，响应会标出该基准。盘中信号只用于同一原始价格坐标内的结构分析，不直接与复权日线价格比较。`/adjusted` 会按逐日有效复权因子转换 15 分钟历史，再生成 4 小时结构供日线信号进行直接下级确认；因子缺失时对应 bars 不参与确认。
- 预览结构包括方向性包含处理、严格分型和旧笔、特征序列线段、同级递归中枢与相邻关系、MACD 力度，以及需要中枢背景、价格创新极值和力度减弱条件的候选观察。返回对象带有级别、来源范围、形成／确认状态和时间；数据缺口、异常跳变及结构修订会进入质量或修订信息。
- `chan-recursive-v4-preview.9` 将分型日期锚定到包含合并组的末根 K 线，同时保留实际极值的原始行情索引；三类位置只从与中枢相交后离开的走势开始判断，标记落在回试端点。结构信号图层在当前窗口无标记时，会区分历史窗口外的信号、尚无绘图位置的候选和全周期无信号。
- `signals_v4` 目前是候选分析输出，不是收益预测。跨级别信号确认、市场过滤和完整一／二／三类买卖点仍以各结构的状态和缺失条件为准；缺少必要数据时不会把状态默认为通过。
- 灰度回退方式：停止客户端对 `/adjusted` 与 `/intraday` 的请求，恢复到 `/api/chan/{symbol}` 和旧版 `strokes`／`centers` 消费路径即可；复权行情、结构快照和原始历史不需要重写或删除。

项目尚无经过成本和样本外验证的 v4 收益报告，不报告未经验证的胜率。回测应使用固定规则版本与逐时点可见的行情前缀，禁止用信号确认日期之后的数据；对相同前缀比较增量计算与全量重算，并报告标的、期间、样本数、信号后观察窗口、基准、交易成本、收益分布、最大回撤、胜率置信区间和样本外结果。样本不足时只报告结构覆盖率，不给出胜率结论。当前升级状态、逐项验收和回放工作见[缠论算法升级规划](docs/chan-algorithm-upgrade-plan.md)，完整可执行定义见[缠论 v4 规则规格](docs/chan-algorithm-rules-v4.md)。

## 部署与启动

部署包需要包含与服务器架构匹配的 Go 服务二进制、`run.sh` 和 `.env.example`。二进制支持 Linux amd64 与 arm64，静态页面资源已嵌入其中。若从源码构建：

```bash
bash ./scripts/build-go-release.sh linux amd64
cp dist/option-scope-linux-amd64 ./option-scope-linux-amd64
```

ARM64 构建将命令参数改为 `arm64`，并将生成的二进制复制为 `option-scope-linux-arm64`。将二进制与 `run.sh` 放在同一目录后，使用运维脚本准备配置并启动：

```bash
./run.sh install   # 检查二进制、创建配置文件和运行目录
./run.sh start     # 后台启动服务；无 systemd 时使用 shell 看门狗
./run.sh status
./run.sh logs
```

首次启动时脚本会从 `.env.example` 创建 `.env`，并自动生成 `ACCESS_KEY`。页面地址为 `http://服务器地址:端口/?key=访问密钥`，默认端口为 8000。服务运行后，可用 `./run.sh stop` 停止、`./run.sh restart` 重启；也可执行 `./run.sh install-service` 安装 systemd 服务。脚本支持的其他操作见 `./run.sh help`。

也可在配置 `.env` 后直接以前台方式运行二进制：

```bash
cp .env.example .env
./option-scope-linux-amd64
```

服务从二进制所在目录读取 `.env`；进程环境变量优先。默认数据库位于二进制旁的 `data/options.db`，相对 `DATABASE_PATH` 也以二进制所在目录为基准。`HOST` 和 `PORT` 可设置监听地址与端口。

开发时，在项目根目录运行：

```bash
go run cmd/go-server/main.go
# 也支持按包运行
# go run ./cmd/go-server
```

`go run` 从当前工作目录读取 `.env`，相对数据库路径也以该目录为基准；识别 Go 临时构建目录及编译缓存中的可执行文件，不受缓存是否命中影响，也支持自定义 `GOTMPDIR` / `GOCACHE`。启动日志 `runtime configuration` 会显示 `.env` 的绝对路径、加载状态、实际端口、端口来源和数据库路径；不会输出访问密钥或 API 凭据。`.env` 不存在时记录 `status=missing`，继续使用进程环境和默认值；文件无法读取或读取中途失败时启动报错。

交互菜单的配置项可编辑 `ACCESS_KEY`、代理和 Alpaca 夜盘凭据。密钥输入不会回显；保存后可选择重启服务。`ACCESS_KEY` 留空时不启用访问保护，生产和局域网部署建议保留访问密钥。URL 中的密钥会进入浏览器历史记录，请避免公开分享完整地址。

生产环境可安装 systemd 服务：

```bash
./run.sh install-service
./run.sh status
```

服务异常后 systemd 会自动重启。查看服务日志：`journalctl -u option-scope.service -f`；卸载托管：`./run.sh remove-service`。没有 systemd 的容器可以使用内置 shell 看门狗，并通过 `./run.sh enable-autostart` 配置开机启动。

遇到 Cloudflare 521 时，先在服务器本机执行 `curl -fsS http://127.0.0.1:8000/health`。本机请求失败时检查 `./run.sh status` 和 `./run.sh logs`；本机成功而公网失败时，再检查 Cloudflare 到源站端口、防火墙、安全组和反向代理配置。

### 启动问题排查

- 二进制无法运行：确认服务器为 Linux amd64 或 arm64，并检查文件名和执行权限。`run.sh doctor` 会检查环境和服务配置。
- 端口被占用：执行 `./run.sh status` 查看服务；确认无关进程占用后，可修改 `.env` 中的 `PORT`。
- 端口与 `.env` 不一致：检查启动日志 `runtime configuration` 的 `dotenv` 路径、`status` 和 `port_source`。`port_source=environment` 表示进程环境中的 `PORT` 覆盖了文件值；开发模式请从项目根目录执行 `go run`。
- 进程因内存不足退出：查看 `./run.sh logs`、系统 OOM 记录及容器 `memory.events` 中的 `oom_kill`；保持 `RESOURCE_MODE=auto`，并确认启动日志中的 `resource budget` 已按实际内存收紧。看门狗的“应用未在运行”只能确认退出，不能单独证明 OOM。
- 确认服务健康：`curl -fsS http://127.0.0.1:8000/health`。

| `EXTREMES_MAX_AGE_SECONDS` | `86400` | 52 周和历史最高/最低价的回源间隔 |
| `SCHEDULER_ENABLED` | `true` | 是否启用定时历史清理和数据库维护；不控制行情刷新 |
| `RESOURCE_MODE` | `auto` | 统一资源开关，只接受 `auto` / `off`。`auto` 启动时检测物理 RAM、cgroup v1/v2（含可见父级）上限和 CPU，自动计算 Go GC 软上限、低内存保护、上游并发与槽位等待时间；`off` 不做任何限制（关闭 Go 软上限，上游并发使用默认上限 6，槽位等待 20 秒） |
| `UPSTREAM_TIMEOUT_SECONDS` | `12` | Yahoo / Alpaca 请求超时秒数 |
| `CBOE_TIMEOUT_SECONDS` | `15` | Cboe 期权请求超时秒数 |
| `GOMEMLIMIT` | 未设置 | 标准 Go 运行时配置；仅 `RESOURCE_MODE=auto` 时作为显式的软上限覆盖，`off` 会关闭软上限。此变量不支持 `auto` |
| `ANALYSIS_CACHE_ENTRIES` | `128` | 压力位/支撑位分析缓存条目数；低内存模式固定为 8，`.env.example` 面向小磁盘预设为 512 |
| `SIZE_CLEANUP_TIME_BUDGET_SECONDS` | `120` | 数据库超限清理每次运行的时间预算；`0` 表示不限制 |

表中「默认值」是环境变量缺失时代码的回退值；`.env.example` 面向小磁盘环境，
已经把 `DATABASE_MAX_MB` 预设为 `256M`、`RAW_RETENTION_DAYS` 预设为 `7`，改成 `0` / 更大的天数即可放宽。

### 资源自动预算

`RESOURCE_MODE=auto` 无需按机器容量手动填写。每次启动（含看门狗重启）都会重新检测环境，并在初始化行情提供方、缓存和 SQLite 前调用 `runtime/debug.SetMemoryLimit`：

1. 实际上限取物理 RAM 和可见容器/父级 cgroup 限制的最小值。
2. 预算取实际上限和启动时可用 RAM 的最小值，Swap 不计入。
3. 预留 `max(预算 × 20%, 32MiB)`；极小预算最多预留一半，结果向下取整到 MiB。检测不到 RAM 时保留运行时原设置并记录日志。
4. 依据同一预算和可用 CPU 计算上游并发与槽位等待；内存上限不超过 4GiB 或可用内存不超过 2GiB 时自动进入低内存模式（重任务串行、缓存缩小）。

例如容器上限约 122MiB、启动时可用约 118MiB，自动 Go 软上限约为 86MiB；实际数值以启动日志 `resource budget` 与 `Go GC memory budget` 为准。

```dotenv
# 自动检测（默认）
RESOURCE_MODE=auto
# 完全不限制
# RESOURCE_MODE=off
```

`off` 会关闭 Go 软上限并取消低内存/并发收紧，仅建议在内存充足或自行负责资源上限时使用。`auto` 下显式设置的标准 `GOMEMLIMIT` 仍会覆盖自动计算值。进程环境对同名 `.env` 项优先。

软限制控制 Go 运行时管理的内存，无法覆盖二进制映射、SQLite 的直接 mmap、内核和文件缓存，也不能强制阻止瞬时大对象分配。因此它降低 OOM 风险，但不保证 122MiB 容器能承受全部请求峰值。默认未设置 `GOMEMLIMIT` 时运行时上限为 `math.MaxInt64`，自动检测是本项目增加的启动行为。

### 性能与请求策略

**上游请求**

- 冷启动时到期日目录与最近到期期权链来自同一次无日期 options 响应，不再先查目录再查链；Cboe 延迟行情也复用同一份 payload。
- 行情走独立交互通道；单独查询到期日时也走该通道。冷启动时目录与最近链合并为一次重任务请求，期权链、历史、Gamma 和基本面共享重任务并发预算；`RESOURCE_MODE=auto` 会按内存收紧，极小内存机器自动降到单槽位。
- 冷启动时历史与复权预取等到快照提交后再启动；复权历史同时写入原始日线缓存，避免重复抓取 2 年日线。
- 盘前、夜盘和休市时，「盘后价」基准取上一个交易日的盘后价：优先用 Yahoo 报价里仍在有效期的盘后价，报价已清零时改读 Yahoo 1 分钟 `includePrePost` 图表中上一交易日 16:00–20:00 ET（早收盘为 13:00–17:00）的最后一根分钟线；该价格在下一个盘后窗口结束前不会变化，按标的缓存到下一次盘后收盘，不进入每次刷新的请求路径。上一交易日没有任何盘后分钟线时退回该交易日收盘价，绝不回退盘前价或夜盘价。
- 低内存模式下估值延迟 2 秒启动，并排在期权链与历史之后，避免基本面请求抢走唯一的重任务槽位。

**传输与缓存**

- 支持 gzip 的客户端会收到压缩后的 JSON；低内存模式使用 `BestSpeed`，约 1.5MB 的复权缠论响应仍可压到约 370KB，SSE 流不压缩。
- `/static/*` 返回 `Cache-Control: public, max-age=31536000, immutable`。页面资源 URL 带内容哈希，Vue、Element UI、jQuery 和业务 JS 首次加载后不再回源校验。
- 浏览器对同一 URL 的并发 GET 做合并；`quote`、`expirations`、`status`、`flow` 和 Gamma 只读状态额外复用 1 秒结果。主动刷新行情或执行 `/api/refresh` 后会立即清除对应的行情/期限短缓存。
- `/api/chan?light=true` 只返回趋势与价位卡片所需字段（约 12KB）；缠论图表默认折叠，展开后才请求复权结构，并带上 `compact=true` 省略图表未使用的字段。
- `/api/levels?raw=true` 只读 SQLite；当日线与 `fast_levels` 已可用时不再附带原始期权行，只有历史缺失、需要期权回退时才返回。首屏尚未选中到期日时按最近有效到期日计算 IV 与触及概率；行情晚于期权链到达时，现价档位变化会自动触发一次价位重算。

**前端渲染**

- 期权链行、分析输入、复权结构、图表视图和盘中 payload 在进入 Vue 2 前冻结顶层，避免为成千上万个只读对象递归建立响应式观察器；表格数据整体替换，从不原地修改。
- Gamma 结果按 0.05% 现价档位复用，行情每跳动一分钱不会重算整条链；期权链指纹使用 32 位滚动哈希（`Math.imul`），不再逐行拼接字符串。
- 成交量、持仓量和热力峰值改为单次遍历；价位选择的权重只计算一次；`Intl.NumberFormat` 按小数位复用，时钟格式化器也只创建一次。
- 缠论历史 K 线、多级结构、条件情景背景、虚线路径、端点以及情景开关全部绘制在同一张 Canvas 上；SVG 只保留十字线读数。情景命中改为按指针到折线的距离判定，情景开关上方覆盖一个透明的 HTML 按钮，继续提供焦点、键盘和原生提示。
- 缠论图下方附带成交量和 MACD（12、26、9）副图，与 K 线共用时间轴；MACD 按完整历史计算并缓存，缩放和平移只切取当前窗口。

### 小磁盘部署（LXC / 512M 磁盘）

512M 磁盘不要按 256M 的数据库来预留。低内存保护开启时会按剩余空间再收紧上限，
并给系统、Go 服务和 SQLite 临时文件留出余量。显式填写的 `DATABASE_MAX_MB` 只会更小，不会比这个预算更大。

把 `DATABASE_MAX_MB` 设为磁盘容量的一半到六成（512M 磁盘建议 `200`-`300`，1G 磁盘建议 `500`-`600`），
后台维护任务每天检查数据库体积（未超限时只读取文件大小，开销可忽略），
超过上限后按阶梯清理，每一步都先看是否已经降到上限的 80% 以下，够用就停下：

1. 清空 `raw_json` 冗余报文（该列只写不读，旧库里约占文件的 68%）；
2. 删除 24 小时之前、已被新批次覆盖的旧快照，每个 `(标的, 到期日, 天)` 保留一批；
3. 仍未降下来时收窄到每个 `(标的, 到期日, 小时)` 保留一批；
4. 继续超限才退到最狠的一档：每个 `(标的, 到期日)` 只保留最新一批，并删除过期刷新记录；
5. 磁盘剩余空间足够（不小于库文件的 1.2 倍）时执行 `VACUUM` 回收文件体积，空间不足则跳过并记录告警，
   等下一轮再回收，避免把容器磁盘写满。

判断「是否降下来」用的是去掉空洞后的有效数据量，而不是文件大小：SQLite 删除行不会立刻缩小文件，
要等 `VACUUM`（WAL 模式下还需要一次 checkpoint）才会真正腾出磁盘。

清理只影响历史冗余批次：最新快照、日线历史、极值缓存的读取路径不受影响；
盘前未平仓量为 0 时的回退逻辑依赖最近 24 小时的历史批次，第 2、3 步都按时间桶给它们留了样本。

另外，新版本不再写入 `raw_json` 冗余报文（列保留以兼容旧库），服务启动时会自动清空旧库中
遗留的报文并回收文件体积，例如 150 MB 的旧库启动后通常会降到 70 MB 左右。

## API

- `GET /api/quote/{symbol}`
- `GET /api/expirations/{symbol}`
- `GET /api/chain/{symbol}?expiration=YYYY-MM-DD`
- `GET /api/flow/{symbol}?expiration=YYYY-MM-DD`（比较同一期限最近两份链快照，估算成交方向与期权流向）
- `GET /api/events/{symbol}?expiration=YYYY-MM-DD`（SSE 推送活跃订阅标的的快照更新通知）
- `GET /api/gamma/{symbol}?horizon_days=45&refresh=true`（跨近期期限的 Gamma 分析链）
- `GET /api/levels/{symbol}?expiration=YYYY-MM-DD&spot=144.57&raw=true`（压力位/支撑位：斐波那契 + 筹码密集 + 承接位 + 所选到期日期权持仓综合，每行含「到达概率」；`spot` 为可选基准价，缺省用快照常规价。`raw=true` 只读 SQLite，并在历史与 `fast_levels` 可用时省略原始期权行）
- `GET /api/chan/{symbol}?spot=144.57&light=true`（日线＋周线缠论结构：包含处理、严格旧笔、笔中枢、当前价相对最近中枢的位置、抄底／逃顶观察与候选、第三类位置候选和条件式走势推演；只读取已落库日线，`spot` 为可选页面现价。`light=true` 只返回趋势/价位卡片所需的市场分析，不返回日／周结构）
- `GET /api/chan/{symbol}/adjusted?spot=144.57&compact=true`（独立复权历史上的递归算法预览；返回规则版本、价格坐标、日／周结构、质量和修订信息。`compact=true` 省略图表不使用的 fractals、MACD、strength 等字段）
- `GET /api/chan/{symbol}/intraday?period=15m|4h&spot=144.57`（已收盘盘中 K 线的递归结构预览；信号使用原始价格坐标，不与复权日线直接比较）
- `POST /api/refresh/{symbol}?expiration=YYYY-MM-DD&max_age=60`（本地快照在 `max_age` 秒内直接返回 `skipped=true`，不再请求上游接口；`max_age=0` 表示强制刷新）
- `GET /api/status/{symbol}`
- `POST /api/cleanup`
- `GET /health`

数据库菜单支持在线安全备份，也支持从备份恢复。恢复会先要求确认、停止服务、检查备份 SQLite 完整性和应用表结构，再保留原数据库及 sidecar 作为回滚副本后替换；操作失败会尝试恢复原文件。发布包中的 `bin/option-scope-go-db restore <backup-path>` 可执行恢复。直接运行数据库恢复工具时，应用服务须先停止。

配置 `ACCESS_KEY` 后，所有页面和 `/api/*` 请求都必须携带正确的 `?key=` 或 `X-Access-Key` 请求头；
只有 `/static/*` 与 `/health` 例外，分别用于加载页面资源和本机看门狗健康检查。
